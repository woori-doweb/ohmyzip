# 3. 판정과 검수
- 각 OZ-R의 scenario/expected/evidence를 모두 충족해야 passed입니다. failed/blocked/not_run/partial을 구별하고 중대 결함과 미실행을 숨기지 않습니다.
- 실제 Windows 창에서 '작업을 완료하는' 시나리오를 수행합니다. 대화상자 진입·버튼 존재·단위 시험·터미널 정상 종료만으로 해당 기능을 완료 처리하지 않습니다.
- 생성→열기→해제→해시, 추가→이름변경→삭제, 암호 정상/오류, 분할 조각 누락/손상, 취소/부분 실패·복구까지 검사합니다. 로그의 테스트 암호도 마스킹합니다.
- 고대비/DPI/동작 줄이기의 실제 OS 시험과 앱 내부 강제 설정/정적 계산은 구분합니다. 사용자 OS 전역 설정을 무단 변경하거나 창 리사이즈를 DPI 시험이라고 보고하지 않습니다.
- 빌드/게시/실제 GUI/증거에 같은 버전·해시를 붙입니다. 기존 정상 0.1 실행판은 새 판 스모크 검증 전 보존합니다. 제3자 라이선스·고지·실행 의존성을 배포 후보에 포함합니다.
- 데이터 손상/루트 탈출/암호 노출 등의 중대 결함이 없고 적용 대상 필수 기준 전부 passed일 때만 전체 완료로 판정합니다. 일부 기준이 막히면 '부분 완료 + 차단 사유 + 다음 행동'으로 보고합니다.
